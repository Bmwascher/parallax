 200: `$env:USERPROFILE\.parallax-kimi-review`; the lane credential is
 201: `<lane-home>\credentials\kimi-code.json`.

 203: **Aggregate verdict, a TOTAL order.** Binary absent short-circuits the
 204: whole row to N/A before the credential or lock checks run. Otherwise the
 205: row is the WORST substate observed, by `BROKEN > STALE > N/A > OK`, and
 206: every substate observed is still named in the detail text. N/A is IN
 207: that order — it is a real row verdict (see the header note above) that
 208: never contributes to overall failure, and without it a valid binary plus
 209: an absent credential plus a free lock would have no defined row.
 210: 
 211: - **Binary and floor.** Run `~/.kimi-code/bin/kimi.exe --version` — the
 212:   client's ABSOLUTE path, never a bare `kimi` resolved from PATH (the
 213:   superseded client can still be installed alongside it). Missing binary

 215:   — the fix pointer is references/backup-lane.md. A present binary that

 221: - **Lane credential structure.** Runs only when the binary row did not
 222:   short-circuit. Invoke `tools/read-kimi-credential-state.ps1 -Path
 223:   <credential-file>` against the configured lane credential, and accept
 224:   the measurement ONLY under the FOUR-PART ACCEPTANCE RULE: the process
 225:   launched, it exited 0, stderr was EMPTY, and stdout was exactly one
 226:   parseable line whose status/detail pairing is one of Task 2's table.
 227:   A process-launch failure, ANY nonzero exit, nonempty stderr, zero or

 233:   - `absent` is N/A, and no hash is taken at all.

 236:   All three credential-failure rows above — `absent`, `unreadable` and

 241:   ```powershell
 242:   & { $ErrorActionPreference = 'Stop'; try { $ownerLines = @(& 'tools/kimi-lane-lock.ps1' -ResolveOwner); $ownerExit = $LASTEXITCODE; if ($ownerExit -ne 0) { throw "owner resolution failed with exit $ownerExit" }; if ($ownerLines.Count -ne 1 -or -not ($ownerLines[0] -is [string]) -or [string]::IsNullOrWhiteSpace([string]$ownerLines[0])) { throw 'owner resolution returned invalid output' }; $owner = $ownerLines[0] | ConvertFrom-Json -ErrorAction Stop; if (-not ($owner -is [System.Management.Automation.PSCustomObject])) { throw 'owner resolution returned invalid schema' }; $ownerFields = @($owner.PSObject.Properties.Name); if ($ownerFields.Count -ne 3 -or -not ($ownerFields -ccontains 'ownerPid') -or -not ($ownerFields -ccontains 'ownerStartTicksUtc') -or -not ($ownerFields -ccontains 'ownerName') -or -not (($owner.ownerPid -is [int]) -or ($owner.ownerPid -is [long])) -or [long]$owner.ownerPid -le 0 -or -not ($owner.ownerStartTicksUtc -is [string]) -or $owner.ownerStartTicksUtc -notmatch '\A[0-9]+\z' -or -not ($owner.ownerName -is [string]) -or [string]::IsNullOrWhiteSpace($owner.ownerName)) { throw 'owner resolution returned invalid schema' }; if ([string]::IsNullOrWhiteSpace($env:TEMP) -or -not (Test-Path -LiteralPath $env:TEMP -PathType Container -ErrorAction Stop)) { throw 'TEMP is not an existing directory' }; $verdictOut = Join-Path -Path $env:TEMP -ChildPath 'parallax-kimi-lane-login-verdict.json' -ErrorAction Stop; & 'tools/new-kimi-lane-login.ps1' -LaneHome '<lane-home>' -OwnerPid ([string]$owner.ownerPid) -OwnerStartTicksUtc $owner.ownerStartTicksUtc -OwnerName $owner.ownerName -VerdictOut $verdictOut; $loginExit = $LASTEXITCODE; if ($loginExit -ne 0) { throw "lane login failed with exit $loginExit" } } catch { throw } }

 245:   **Hash procedure, a seven-step algorithm run around the validator call
 246:   above so a hash failure never leaves the validator substate
 247:   unmeasured:**
 248:   1. Test existence of the credential file.
 249:   2. If ABSENT: run the validator, require `absent`, take NO hash.
 250:   3. If PRESENT: attempt hash 1 (SHA-256 of the file's bytes) and record
 251:      success or failure.
 252:   4. Run the validator REGARDLESS of hash 1's outcome.
 253:   5. If the file is still present, attempt hash 2. Disappearance between
 254:      the two hashes is BROKEN.
 255:   6. Compare ONLY if both hashes exist. Never compare a missing value to
 256:      anything.
 257:   7. Any hash failure is BROKEN, and it does NOT suppress the validator
 258:      detail.

 260:   A hash that cannot be taken on a PRESENT credential is BROKEN. The two
 261:   hashes show only that bytes changed during the interval, never WHO
 262:   changed them: differing hashes are BROKEN, "credential bytes changed
 263:   during the check; actor not established"; equal hashes are reported as
 264:   "no net byte change observed", never as proof nothing wrote the file.

 267:   check 8. It acquires the lane lock, it MAY REFRESH the dedicated
