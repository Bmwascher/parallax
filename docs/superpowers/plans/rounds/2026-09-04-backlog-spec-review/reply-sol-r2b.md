### New vacuous-control risks

- Stop and pre-push require only changed `BACKLOG.md` bytes. Because the entire `Verified` line is excluded from its digest, changing only an unrelated item’s date—forward or backward, provided it is not future—passes lint and satisfies both hooks without reviewing the owning item (`docs/superpowers/specs/2026-09-04-backlog-rewrite-design.md:106`, `docs/superpowers/specs/2026-09-04-backlog-rewrite-design.md:275`, `docs/superpowers/specs/2026-09-04-backlog-rewrite-design.md:300`). Changing an unhashed preamble byte is another valid escape (`docs/superpowers/specs/2026-09-04-backlog-rewrite-design.md:54`, `docs/superpowers/specs/2026-09-04-backlog-rewrite-design.md:107`). Impact: high. Require a structured review attestation bound to the session baseline or pushed range and an item ID, or explicitly classify both hooks as reminders rather than controls.
- After Stop blocks once, the next Stop carries `stop_hook_active`; the design exits zero before rechecking, so stopping again ends the session without correction (`docs/superpowers/specs/2026-09-04-backlog-rewrite-design.md:246`, `docs/superpowers/specs/2026-09-04-backlog-rewrite-design.md:272`). Missing baseline or Git is likewise fail-open (`docs/superpowers/specs/2026-09-04-backlog-rewrite-design.md:284`). Impact: high. The design cannot promise both “cannot finish” and one-shot Stop blocking; narrow Stop to an enforcement prompt and identify pre-push/CI as the hard controls.
- Rule 9 accepts an empty `**What remains.**` paragraph, and rule 10 accepts any `Record:` line without proving it resolves (`docs/superpowers/specs/2026-09-04-backlog-rewrite-design.md:125`, `docs/superpowers/specs/2026-09-04-backlog-rewrite-design.md:225`). Impact: medium. Require nonempty remainder text and validate `Record:` as either an existing retained path or a resolvable commit.
