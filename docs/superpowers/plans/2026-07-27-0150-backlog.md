# parallax 0.15.0 backlog

Seeded 2026-07-27. Four items, carried out of the 0.14.2 to 0.14.4
cycles. None is started. Ranked by how much each one currently costs.

## 1. Replace the pin mechanism

**Problem.** Contract text is locked by hand-written substring pins. A
pin can stay green while the operative half of the sentence it claims to
lock is deleted.

**Evidence.** Twelve instances across three consecutive cycles: nine in
0.14.2, two in 0.14.3, one in 0.14.4. Two of them appeared inside the fix
for the previous one. In 0.14.4 the pinned string occurred twice in the
same file, so it did not lock even the paragraph's existence.

**Why it is not fixed yet.** Every reviewer seat that looked at it agreed
a follow-on cycle is the wrong vehicle for a mechanism redesign, and that
forcing one in would skip the plan-debate gate.

**Shape of a fix, not decided.** Options include anchored block pins,
a checksum over a marked region, or generating pins from the doc rather
than writing them by hand.

## 2. Make the auto-triage lane fail loudly

**Problem.** The headless drift auto-triage is the unattended safety net.
It can die and leave no signal.

**Evidence.** The 2026-07-21 run exited 1 on `You're out of usage
credits` and sat unnoticed for six days across five releases. Its own
runner also logged a second error: `Write(**) is not matched by file
permission checks, use Edit(**) instead`. Nothing surfaced either until a
human opened the folder.

**Two parts.** Fix the wrong permission rule in the runner's
`--allowed-tools`. Then make a failed triage raise something the user
sees, the same way a finding does.

## 3. Fix the attestation verifier's warning text

**Problem.** The pre-push message contradicts itself. It reports the
attestation as PASS, FULL, and route-confirmed, then says one of those is
required.

**Cause.** `tools/verify-attestation.ps1:49` requires `route_note` to
equal the exact token `effective route confirmed`. Any other text fails
the match, and the failure message prints the record's real values, which
read as a pass.

**Confirmed working.** 0.14.4 pushed with the exact token and the lane
reported `attestation: attested:` with no warning. So the rule is right
and only the message is wrong.

## 4. Reduce preflight-3 friction in repos that legitimately carry back-channels

**Problem.** Preflight 3 stops the gate in any repo that carries an
`AGENTS.md` or `.agents/skills/*/SKILL.md`. The stop is correct: codex
ingests `AGENTS.md` as instructions and advertises repo-level skills to
the model, so reviewing over them lets the repo tell the auditor what to
think. But the remediation is hand-built every single time, and the gate
asks for a fresh go-ahead on every run.

**Evidence.** Observed 2026-07-27 in another project, atrocityEssentials:
18 entries blocked the gate, one root `AGENTS.md` plus 17
`.agents/skills/*/SKILL.md` files. The same block had already been
cleared in an earlier session there. The user was offered the same two
options again: build the mirror by hand, or abort the gate.

**Why this matters.** A correct gate that is expensive to satisfy gets
skipped. The abort option routes to a deferred diff gate, which means the
easy path is the one with less verification. That is the wrong gradient.

**What already exists.** `references/backup-lane.md` defines the mirror
and says preflight-3 remediation is performed there, never in the real
tree. It is driver-executed prose, so a human or agent rebuilds it by
hand each run.

**Shape of a fix, not decided.** Candidates, in rough order of appeal:

- Make mirror construction plus remediation a single scripted step, so
  the gate offers one action rather than a procedure.
- Cache the remediated mirror per repo and commit, and rebuild only when
  the tree or the back-channel set changes.
- Record a per-repo standing decision, so a repo whose back-channels are
  known and already remediated does not re-ask on every run.

**Constraint that must survive any fix.** The block itself is not the
problem and must not be softened. The remediation must stay inside the
mirror, and the deletion must still be committed there so the reviewer
cannot read the files. Making it cheaper must not make it optional.
